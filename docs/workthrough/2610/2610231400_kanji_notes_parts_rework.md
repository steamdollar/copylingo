## 리뷰어별 특성 (판정할 때 참고한 경향)

- **codex**: 금지 규칙(뜻 변천)을 가장 엄격하게 적용했다. 물길을 터서 → 결정하다 같은 한 걸음짜리 연결까지 지적했다. 이런 짧은 연결은 대부분 기각하고 유지했다. 근거 URL을 붙였다.
- **Gemini 3.8 Flash**: 지적이 가장 많았다. 說文과 반대되는 주장("對는 형성", "向은 단일 상형")도 섞여 있어서 근거 대조가 필요했다. 부품 훈음 대표훈 지적은 유용했다(陵의 夌, 隔의 鬲, 陸의 坴).
- **Gemini 4 Argon**: 亦聲 처리, 보이는 모양과 원래 부품이 다른 경우(句의 勹, 可의 丁)를 정확히 짚었다. codex 사용 한도 이후 대체로 썼다.
- 두 리뷰어가 같은 지적을 한 경우는 거의 모두 수용했다(射의 身, 罪, 臨, 育, 風).

## 판정 규칙 (재생성·수정 때 그대로 적용)

- 부품 역할 type은 說文 풀이를 1순위로 따른다. 亦聲은 형성으로 둔다. 단, 설명이 발음 부품의 뜻을 써야만 성립하면 회의로 둔다(酒, 墨).
- 보이는 모양이 원래 부품과 다른 글자면 `form` "발음 부품 X가 바뀐 모양"으로 쓴다(句·可·叱). 원래 글자와 거의 같은 신자체 변형이면 원래 글자를 parts에 두고, 설명에 "X는 오른쪽 모양의 원래 글자다"를 붙인다(渇·掲의 曷, 痩·捜의 叟).
- 발음 부품의 `on`은 부품이 실제로 흔히 갖는 음일 때만 쓴다. 사전의 드문 읽기만 근거면 뺀다(灯의 丁 トウ, 碁의 其 ゴ).
- 부품 훈음 후보가 리뷰어끼리 갈리거나 확실하지 않으면 비운다(蒦·耤·喿·丂 등).

## 이번 작업에서 배운 것 (도구)

- **codex sandbox**: 이 환경의 `codex exec --sandbox read-only`는 bwrap 오류로 파일을 못 읽는다. 검수 자료는 prompt에 그대로 붙여야 한다. git 저장소 밖에서는 `--skip-git-repo-check`가 필요하다.
- **codex 사용 한도**: 동시에 10개 넘게 호출하면 "at capacity", 이어서 usage limit(약 4시간)에 걸린다. 그 뒤 Gemini 4 Argon(`agy --model gemini-4-argon --effort high`)으로 대체했다.
- **Gemini CLI**: `gemini` CLI의 개인 무료 인증은 종료됐다. `agy`(Antigravity CLI) `-p --model gemini-3.8-flash --effort high --sandbox`로 호출한다.
- **실행 중 bash script 수정 금지**: bash는 script를 실행하면서 읽는다. 돌고 있는 `run_review.sh`를 고쳤더니 job이 exit 2로 깨졌다.
- **`pgrep -f` 자기 매칭**: `while pgrep -f "run_review.sh"` 대기 loop가 자기 자신의 명령줄과 매칭돼서 끝나지 않았다. 대기 조건은 완료 파일(`done.log`)로 확인한다.
