# 단어별 한자 읽기(`kanji_readings`) 생성·검증

- 날짜: 2026-10-19
- 결정: [ADR-074](../../adr/ADR_from_61_to_80.md#adr-074-한자-해설의-읽기는-같은-부품이-아니라-이-단어에서-그-한자를-어떻게-읽는지로-보여-준다)
- 계기: 2026-10-19 21시 Study 세션(session 621)에서 해설이 단어 읽기와 안 맞음. 伺う(うかがう)에 司(シ), 伸ばす(のばす)에 申(シン), 橋(はし)에 喬(キョウ), 降りる(おりる)에 夅(コウ)

## 원인 확인

- DB payload는 seed JSON과 같았고, 돌고 있던 server는 최신 코드였다. 렌더링도 material ID로 해설을 찾아서 카드가 뒤섞이지 않았다.
- 해설 내용(字源) 자체는 대체로 맞았다. 문제는 해설이 **한자 단위**인데 화면은 **단어 카드**라는 점이었다. 훈독 단어에도 발음 요소의 음독이 붙었다.

## 근거 수치 (seed N3–N5)

| 측정 | 결과 |
|---|---|
| 발음 요소가 있는 해설 중 단어 kana에 그 음이 나오는 것 | 646 / 1,843 (35%) |
| 발음 요소의 음 = 그 한자의 음독 | 1,073 / 1,843 (58%) |
| 한자어(한자 2자 이상, 꼬리 없음)에서 그 한자의 음독이 단어 읽기에 나옴 | 580 / 640 (90%) |
| 한자 1자 + 꼬리 단어에서 같은 측정 | 78 / 433 (18%) |
| 음독으로 쓰인 한자 중 우리 어휘 안에서 음독이 1종류 | 959 / 1,018 (94%). 2종류 이상 예: 生 セイ/ショウ, 大 ダイ/タイ, 図 ズ/ト, 地 チ/ジ |

- 마지막 두 수치는 단어 하나에만 나오는 한자도 1종류로 세서 실제보다 조금 높다.
- 그래서 "같은 부품 → 다른 한자의 음"(58%) 대신 "이 한자 → 이 한자의 음독"(90%)을 보여 주기로 했다.

## 생성 절차

`scripts/gen_kanji_readings.py`가 한다. 입력 파일은 저장소에 넣지 않는다.

| 데이터 | 용도 |
|---|---|
| JmdictFurigana | 단어 읽기를 한자별로 나눔 (場所 → 場=ば + 所=しょ) |
| KANJIDIC2 | 한자별 음독 목록. 나눈 읽기가 여기 있으면 음독(연탁·촉음 허용) |
| JMdict | 일반 어휘(`news1`·`ichi1`·`spec1`·`spec2`·`gai1`) 판정. "이 한자의 음독" 줄은 일반 어휘에서 실제로 쓰는 음독만, 많이 쓰는 순으로 최대 3개 |

정렬은 단어 그대로 → `する` 뗀 형태 → 앞의 `お`·`ご` 뗀 형태 순서로 찾는다.

## 처리 수치

| 단계 | 결과 |
|---|---|
| 대상 | 한자가 있는 어휘 2,961개 |
| 자동 정렬 | 2,920개 (98%). 남은 41개 중 35개는 `する` 떼기(32)·`お` 떼기(3)로 해결 |
| 수작업 정렬 (`MANUAL`) | 9건: 정렬 실패 6단어(可愛らしい, 真っ赤, 良い(いい), 顔を洗う, 二匹, 三匹) + 日本(にほん·にっぽん)·日本語 3건. 日本은 JmdictFurigana가 한 묶음으로 둬서 熟字訓으로 잘못 나왔다 |
| 판정 보정 (`TYPE_OVERRIDE`) | 5건: 差す·放る는 상용한자표상 훈독인데 음 형태와 같아서 훈독으로 고정. 日本·日本語의 日=に, 文字의 文=も는 줄어든 음독이라 음독으로 고정 |
| 최종 | 음독 2,990 · 훈독 1,575 · 熟字訓 44 |
| 함께 정리 | note의 `series` 628개 복사본 제거 |

### 오판 점검 방법

- 한자 1자 + 꼬리 단어인데 음독으로 판정된 43건을 전수로 봤다. 差す·放る 2건 외에는 お茶·死ぬ·感じる처럼 실제 음독이었다.
- 훈독으로 판정됐지만 읽기가 음독의 앞부분과 겹치는 8건을 봤다. 文字(も) 1건만 줄어든 음독이었다.
- 熟字訓 44건은 상용한자표 付表 기준으로 봤다. 日本 외에는 모두 맞았다(今日·大人·上手·真面目 등).

## 새 단어에 읽기 붙이기

1. 입력 파일 세 개를 받는다 (KANJIDIC2 `kanjidic2.xml.gz`, JMdict `JMdict_e.gz`, JmdictFurigana `JmdictFurigana.json`. 주소는 script 머리말에 있다).
2. `python3 -I scripts/gen_kanji_readings.py <kanjidic2> <JMdict> <JmdictFurigana>`로 먼저 돌려 `unaligned` 목록을 본다. 있으면 `MANUAL`에 넣는다.
3. `--write`를 붙여 다시 돌린다. 출력은 결정적이라 기존 단어 줄은 바뀌지 않는다.
4. `go test ./cmd/seeding/`로 형식과 한자별 음독 일관성을 확인하고, 재seed한다.

## 검증

- script를 다시 돌리면 seed JSON이 byte 단위로 같다 (scratch에서 만든 결과와 비교).
- `go test ./...` 통과
- 실데이터 렌더링 확인: 伺う(훈독 줄만, 음독 줄 없음), 伸ばす(の 훈독 + 음독 シン), 事故(note 없는 事도 표시), 先生(生 セイ · ショウ), 今日(단어 전체 읽기)
