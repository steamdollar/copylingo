# ADR-051: 사용자별 자료 유지 복습·제외 설정과 공통 출제 기한

- 날짜: 2026-09-25
- 상태: 승인됨

## 배경

사용자가 이미 알고 있거나 필요하지 않은 자료를 개인별로 지정하려 한다. 현재 Study와 Quiz는 각각 `user_material_progress`와 `user_question_progress`에 복습 일정을 갖는다. Study의 다음 복습일 전에도 같은 자료의 다른 Quiz가 신규 또는 복습으로 출제될 수 있다. 자료 전체에 대한 사용자 의도와 실제 학습 이력을 분리해야 한다.

사용자는 일반 학습·유지 복습·학습 제외와 자료 단위 `next_check_at`을 승인했다. 이미 생성된 대기·진행 세션에 소급 적용하지 않으며, 자리 비움 중 구현·검증·마무리를 위임했다.

## 결정

- `user_material_preferences(user_id, material_id)`에 유지 복습 또는 제외 설정만 저장한다. 행이 없으면 일반 학습이다. 공유 catalog와 두 progress 테이블의 이력을 삭제하거나 초기화하지 않는다.
- 필드는 `review_mode`, `next_check_at`, `check_interval_days`, `created_at`, `updated_at`이다. FK·복합 PK·모드/기한 CHECK를 둔다. 기존 progress의 행 존재 여부를 신규 판정에 사용하는 의미를 유지한다.
- 제외 자료는 새 Study와 연결 Quiz의 신규·복습 후보 및 복습 개수에서 제외한다. 유지 복습 자료는 `next_check_at` 전까지 같은 경로 모두에서 제외한다. 후보 필터는 순위·LIMIT·부족분 보충 이전에 적용한다.
- 유지 복습은 초기 30일 후부터 가능하다. 실제 확인 Quiz를 맞히면 60→120→180일로 늘리고 180일을 상한으로 둔다. 오답이면 일반 학습으로 복귀한다. 이 간격은 학습 연구가 보장한 최적값이 아니라 조정 가능한 초기 운영값이다.
- 기한이 지나도 기존 문제별 SRS 기한, 자료 선행 학습, audio 준비 조건을 무시하지 않는다. 출제 가능한 연결 Quiz를 우선하고 한 자료의 여러 변형을 동시에 유지 복습으로 선택하지 않는다. 확인 Quiz 후보가 없으면 기존 조건을 만족하는 Study를 허용하며, 읽음은 숙련 증거가 아니므로 유지 간격을 늘리지 않고 같은 간격으로 다음 기한을 잡는다.
- 유지 복습의 대표 Quiz는 due 우선, 다음으로 신규인 결정론적 후보로 정해 분산된 세션 편성 경로에서 같은 자료의 다른 변형이 중복되는 것을 방지한다.
- 조회 범위가 다른 현재·인접 레벨의 후보를 합칠 때도 세션 조립 단계에서 유지 자료별 1문제를 보장한다. 후보의 `IsMaintenanceCheck`는 조회 결과에만 붙는 일시적 정보이며 catalog DB나 JSON/Redis에는 저장하지 않는다. 일반 자료의 여러 변형 문제는 계속 허용한다.
- 기존 세션 목록·Redis working set은 바꾸지 않는다. 설정 안내에 새 세션부터 적용한다고 표시한다. 이전에 생성된 세션의 완료 결과가 나중에 바꾼 설정을 되돌리지 않도록, 자동 전환은 해당 설정과 출제 가능 기한 이후 생성된 세션에만 적용한다.
- 설정 저장은 즉시 DB에 반영한다. 결과에 따른 전환은 기존 세션 완료 transaction에서 학습 이력과 함께 처리하며 완료 재시도로 중복 갱신하지 않는다. 같은 모드를 다시 선택해도 복습 기한을 연장하지 않는다.
- Study 카드에서 정책을 바꾸고 설정 메뉴의 페이지 목록에서 확인·일반 학습 복원이 가능하다. 연결 자료가 있는 Quiz 문제에서는 유지 복습·학습 제외 두 선택지를 먼저 보여 준 뒤 선택한 설정만 저장한다. Quiz callback은 사용자 소유권과 문제의 세션 membership을 확인해 서버 측 `material_id`를 사용한다. Quiz 설정을 바꿔도 현재 세션의 문제·답안은 바꾸지 않는다.
- `material_id`가 없는 청해 등은 이번 자료 단위 정책의 대상이 아니다. 기존 세션 소급 수정, 자료의 물리 삭제, 질문 단위 제외 설정은 추가하지 않는다.

## 규모와 절충

- 설정은 사용자별로 지정한 자료에만 생기는 sparse row이며 전체 사용자×자료 조합을 만들지 않는다. `(user_id, material_id)` PK로 기존 PostgreSQL 후보 조회 안에서 적용하고 설정 목록은 페이지 단위로 조회한다.
- 별도 테이블 join과 유지 복습 대표 문제 선정 비용이 추가된다. 사용자별 전체 catalog를 앱으로 읽거나 새 캐시·큐를 추가하지 않는다. 기존 자료 FK 인덱스와 사용자별 progress PK를 활용한다.
- 유지·제외 자료로 인해 후보가 줄면 기존 허용된 후보로 보충하고, 부족하면 짧은 세션을 허용한다. 금지 자료나 미래 SRS를 당겨 수량을 채우지 않는다.
- 유지 복습 대표 문제를 결정론적으로 고르면 무작위성이 줄지만, 한 자료의 여러 문제에 별도로 SRS를 부풀리는 것보다 정책을 일관되게 적용할 수 있다.

## 검증·배포

- 사용자 격리, 미학습 자료의 설정·복원, 신규/due/count/보충 경로의 gate, 연결 없는 문제, 자료별 한 문제, 정답·오답·오래된 세션 완료 및 중복 완료를 검증한다.
- Telegram 소유권·membership·잘못된 callback·페이지 이동·복원과 기존 Study 진행 보존을 검증한다.
- 로컬 PostgreSQL에는 `001_init.sql`의 새 테이블 생성문만 additive하게 적용한다. 기존 이력과 설정을 지우는 down migration을 사용하지 않는다.
- 실제 PostgreSQL 임시 테이블 검증을 포함한 `make test` 후 `make restart-app`과 `/health`를 확인한다.
